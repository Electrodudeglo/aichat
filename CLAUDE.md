# Project instructions

## Git workflow

- When committing changes, stage and commit each changed file individually (one commit per file), rather than bundling multiple files into a single commit. This lets the user track exactly what changed in each file via the commit history.
- Commit message format: always `Claude: <short description>`. The description should simply state what changed or was added in that file — nothing else. No session links, no attribution lines, no extra detail beyond the change itself.

## Code style

- Don't add comments inside the files.
